# Skills

`skills/` 现在是 RedAnet 的轻量能力目录，不是 vendor 仓库，也不是一套提前做满的评级系统。

这里先解决一个很现实的问题：我们需要快速看清楚哪些 Skill 值得收、值得试、值得以后变成 RedAnet 自己的能力包。

## 这是什么

这个目录用来记录两类东西：

- `实用主线`：已经明显贴近 RedAnet 近期任务形态的方向
- `有趣实验区`：值得观察、试玩、借鉴 workflow 形状的外部 Skill 项目

它的目标不是证明我们已经“拥有”这些 Skill，而是把收集、筛选、试装之前的判断前置做好。

## 为什么现在做

之前这里只有两个极端：

- [README](./README.md) 太薄，只像一句口号
- [DESIGN](./DESIGN.md) 太重，像一份还没到执行阶段的平台白皮书

中间缺了一个真正可用的目录页。我们现在先把入口做轻，先让人两分钟内看懂：

- 这个目录在干什么
- 现在优先收哪些方向
- 哪些项目只是灵感来源，还没有被验证

## 实用主线 Skills

这部分只保留 4 个轻量方向，不再提前展开成多层 taxonomy。

| 方向 | 现在重点看什么 | 为什么现在值得收 |
| --- | --- | --- |
| 工程协作 | code review、代码库理解、测试补强、迁移与重构工作流 | 最接近 RedAnet 近期“接单-交付-验收”的真实任务 |
| 研究与证据整理 | web research、代码调研、证据汇总、比较分析 | 能直接提升报价、方案判断和验收质量 |
| 工作流与集成 | GitHub、MCP、handoff、自动化触发 | 适合把单点能力接成多 Agent 协作流程 |
| 文档与数据处理 | PDF / DOCX / PPTX / XLSX、数据清洗、结构化摘要 | 企业侧高频输入输出，适合沉淀模板化交付 |

## 有趣的 Skills（实验区）

以下条目全部是外部项目或灵感来源：

- 不代表 RedAnet 已采用
- 不代表我们已验证可用
- 不导入第三方 `SKILL.md`、脚本或资源文件

我们只记录它们为什么有意思，以及哪种 workflow 形状值得借鉴。

当前实验区的最低收录门槛：

- `stars >= 100`，或者能看到明确的公开讨论信号
- 公开讨论信号至少要有一项说得出口，例如：持续 issue、明显 fork、被反复引用、进入公开列表
- `stars < 100` 且几乎没有公开讨论的项目，先不收录

| 名称 | 来源 | 一句话看点 | 可借鉴的 workflow 形状 | 当前状态 |
| --- | --- | --- | --- | --- |
| `colleague-skill` | [titanwings/colleague-skill](https://github.com/titanwings/colleague-skill) | 把同事的经验与表达方式蒸馏成可调用 Skill | 采集材料 -> 提炼行为模式 -> 生成可调用 persona/workflow | `want-to-try` |
| `anti-distill` | [leilei926524-tech/anti-distill](https://github.com/leilei926524-tech/anti-distill) | 反向处理 Skill 文件，把“看起来完整”和“核心知识”拆开 | 文档分层 -> 清洗版输出 -> 私人备份保留核心判断 | `watching` |
| `nuwa-skill` | [alchaincyf/nuwa-skill](https://github.com/alchaincyf/nuwa-skill) | 强调“蒸馏任何人的思维方式”这件事本身 | 人物材料 intake -> 心智模型抽取 -> 通用模板复用 | `watching` |

状态说明：

- `watching`：先观察，不急着试装
- `want-to-try`：值得后续单开 issue 试一试

## 收录原则

- 先看它是不是一个连贯 workflow，不先讨论宏大 taxonomy。
- 实用主线优先贴近近期任务；有趣实验区允许整活，但必须说清楚“为什么 RedAnet 该关心它”。
- 每个实验条目都必须带来源链接和一句明确说明，避免被误读成“已经采用”。
- 有趣实验区默认要求 `stars >= 100`，或者有足够明确的公开讨论信号；不收低星且几乎无讨论的孤立项目。
- 默认不 vendoring 第三方仓库内容；先记录、再筛选、后验证。
- 如果一个条目已经需要本地试装、脚本适配或验证，就应该单开 issue，不在这个目录页里偷偷升级复杂度。

## 下一步

- 继续按“小批量增补”的方式往实验区加条目，不追求一次收全。
- 如果某个实验条目被反复提起，或者确实适合 RedAnet 任务形态，再单开 issue 做试装和筛选。
- 如果未来真的出现稳定、可复用、需要本地封装的 Skill，再考虑新建项目级 `.codex/skills/` 或独立 Skill 包目录。
- 具体的边界和最小模板，见 [DESIGN](./DESIGN.md)。
